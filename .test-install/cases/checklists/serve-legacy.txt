1) 被测对象是**旧 tarball 装出来的**那份 runtime：先确认启动时打印的 dsh 版本是
   0.1.3-alpha.2（该实例记录的版本）。不一致则本项直接失败，不必往下做。
   注意：这份产物**没有**后续版本才有的补丁（例如 landlock tmpdir），所以
   `$TMPDIR` 写入、会话保存这些**不要**按当前版本的标准要求它。

2) 它能不能真的启动 Web：`dsh web --port <端口>` 后页面能打开、标题是 DeepSeek Harness。
   （这是本清单的核心——0.1.3 当年死在这一步：缺 fs-ext 原生件时 loader 起不来。）

3) 若第 2 项起不来，把**浏览器/终端里原样的报错**贴回来（尤其 `Cannot find module`
   一类）。这条路径**不许**用 overlay 当前 scripts/patches 去"修好"再测——那样测的
   就不是这份旧产物了。

4) 边界：全程本地正在运行的 dsh runtime 不受影响（`~/.dsh` 与 127.0.0.1:3080）。

5) 说明「未实测」的判据：本清单**只**主张"这份已发布旧产物在真机上能装能起"。
   它**不**主张 npm 路径、`--self`、机件刷新、升级、也不主张"退役原生件机件"这件事
   被验证过（那条代码不在这条执行路径上）。凡超出本范围的问题，请另开记录。
