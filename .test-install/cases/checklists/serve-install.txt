1) 被测对象是**安装路径装出来的**那份 runtime: 先确认启动时打印的 dsh 版本与安装目标一致
   (若不一致, 本项直接失败, 不必往下做)

2) 页面能打开, 标题是 DeepSeek Harness
   (打印的 URL 是一次性握手 ?token= -> 303 -> 会话 cookie; 兑换成功后地址栏只剩 127.0.0.1:<端口>)

3) 新建会话并发送一条消息, agent 能回复
   (沙箱默认无真实凭据, 提示缺 API Key 属预期; 未配凭据时本项只能标「未实测」)

4) 让 agent 写一个文件再读回来, 确认落点在沙箱工作区里 —— 证明装出来的 runtime 真的能干活,
   而不只是能 `--version`

5) 让 agent 在 bash 工具里执行 mktemp -d 与 echo x > "$TMPDIR/t" && cat "$TMPDIR/t":
   预期都成功且落在沙箱 tmp/ 里 (安装链路必须把补丁集一并装上, 这里失败说明补丁没进去)

6) 浏览器交接: 启动时自动弹出的那次就是它。serve 默认不插桩, 不对"弹没弹"下结论——
   弹出、页面正确即通过; 没弹出请把 dsh 打印的 URL 手动打开并说明"自动弹出失败"

7) 边界检查: 全程本地正在运行的 dsh runtime 不受影响 (~/.dsh 与 http://127.0.0.1:3080)

8) Ctrl-C 退出后, 本地原来的 dsh web 仍能正常打开
