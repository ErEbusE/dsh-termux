本清单的对象是 update/support-floor：一棵**被断言过**的种子 runtime（不是"更新成功
后的"那棵）。它验的是"该拒绝的被拒绝、且没有副作用"，不是更新本身。

1) 让 agent 在 bash 工具里跑一次低于支持下限的更新目标（例如
   `bash scripts/update-dsh.sh -v 0.1.4 -y`，路径以沙箱 runtime 内的实际位置为准）：
   预期**非零退出**，且它说得出"低于 0.1.5-alpha.1 所以拒绝"

2) 拒绝消息读起来是够用的：点明版本、下限、理由（dsh 0.1.3/0.1.4 需要的原生件本项目
   已不再构建/分发），并给出**可照做**的替代路径（install.sh -p 或
   DSH_RELEASE=<tag>）。它**不得**承诺一个并不存在的 release —— npm 上有版本不等于
   本项目有对应发布物

3) 被拒绝之后，这棵树仍然能用：`dsh --version` 与页面/会话的行为与实测开始时一致
   （拒绝发生在 npm 改写安装树之前，所以这里不该有任何变化）

4) 同一件事在另一个入口也要成立：让 agent 用
   `DSH_VERSION='@deepseek-ai/dsh@0.1.4' bash scripts/02-install-dsh.sh`
   再跑一次，确认同样被拒绝、同样没有改动安装树

5) 边界检查：全程本地正在运行的 dsh runtime 不受影响（~/.dsh 与 http://127.0.0.1:3080）

6) 范围限定：本清单**不**验证"旧版本用 tarball 装得上"——那条路径另有欠账
   （STATUS.md 进度表的 11d ＋ DECISIONS.md 的 ADR-001 落地记录），未实测就标「未实测」。
